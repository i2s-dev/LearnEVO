EvoERP · Inventory · Warehouse Control

The field says “Q.” The transfer still won’t move.

Bin-to-bin transfers (IN-L-J) don’t check the “Q” you see on screen. They check a second, hidden layer of bin records underneath it. When the two disagree, the transfer quietly refuses — and re-typing “Q” is what secretly repairs the hidden layer.

The model

Two separate things have to agree for a transfer to work

Layer 1 — what you see in WC-B

Warehouse Control = Q

Stored in BKICLOC.BKIC_LOC_WHCTRL. This is the only thing on the screen — so it looks like everything is fine.

must match ↓

Layer 2 — what IN-L-J actually reads (hidden)

a default bin exists  ·  bin on-hand is in sync

Stored in ISBINLOC (default-bin flag ISBIN_LOC_DFLT=Y, bin qty ISBIN_LOC_UOH). Not shown anywhere on the WC-B screen.

Broken vs. healthy

Same “Q” on top — different reality underneath

The bug (PCB & WCL items)

Q
  • No default bin, or bin records missing
  • Bin on-hand stale / doesn’t match location on-hand
  • Lot/serial rows never linked
✗Transfer blocked

Healthy item

Q
  • Default bin present (DFLT=Y)
  • Bin on-hand reconciles to location on-hand
  • Lot/serial rows linked
✓Transfer posts

The three ways to “fix” it

Only one actually repairs the hidden layer

Re-save “Q” in WC-B

per item, or via F6 Ranges
Saving re-runs EVO’s bin-configuration routine — it rebuilds the default ISBINLOC record and re-links lot/serial bins. The repair is the side effect of saving, not the value.
✓ Fixes it

Bulk SQL update

SET WHCTRL = 'Q'
The value is already “Q,” so the write changes nothing — and it never triggers the bin reconciliation. Looks done; fixes nothing.
✗ No effect

Toggle N ↔ Q or Y ↔ Q

to force a rebuild
WC-B warns that turning control off purges bins and switching to Y zeros bin quantities. It would rebuild — by destroying on-hand data.
⚠ Destructive

So, for “all PCB items”: run it through WC-B → F6 Ranges filtered by the PCB Class/Category — not a database update. Test one known-broken item first and confirm a bin transfer then posts; if Ranges skips rows already flagged “Q,” each still needs an individual re-save.
