# M-002: suwin6.dcy "binary opcodes" finding was WRONG
**Status:** CORRECTED
**Date:** 2026-06-29 (Pass 375)
**Keywords:** suwin6.dcy, DCY, decryption, cipher parameters, Delphi form, TEditForm, stale binary, entropy

## Symptom
Prior research (Pass 112, 2026-06-17) claimed suwin6.dcy decrypts to "pure compiled TAS Pro 7 bytecode / binary opcodes". The `samples/suwin6_decrypted.bin` (32,864 bytes) looked like binary garbage with entropy 7.99 bits/byte and zero readable strings.

## Root Cause
The `suwin6_decrypted.bin` was generated by a pre-confirmation decryptor that used incorrect cipher parameters (wrong P_start, or wrong key padding). The file was stale from before the cipher was fully confirmed (2026-06-16). The stale binary was never regenerated after the cipher fix.

## Attempts
**Fix (Pass 375):** Re-ran decryption using correct parameters (K_C + 4 zeros, P_start=K0). Result: `object EditForm1_1: TEditForm1_1` — plaintext Delphi VCL form (ISTech License dialog). `samples/suwin6_decrypted.bin` regenerated. `decryption-findings.md` and `dcy-forms-catalog.md` updated with correct findings.

## Resolution / Lesson
Always regenerate sample files from scratch when cipher parameters change. A stale binary that looks encrypted is indistinguishable from a correctly-encrypted-binary-format file — don't infer format from broken output.
